## Current Status

The `fh_mps` notebook exposed a mismatch after imaginary-time evolution on a
4 by 3 periodic square lattice mapped to a snake MPS chain:

```text
<H>/N (terms): -0.297362   <H>/N - U/4: -2.297362
<H>/N (mpo):   +0.175258   <H>/N - U/4: -1.824742
```

The local-term energy is computed from the original Symmray fermionic two-site
Hamiltonian terms. The MPO energy is computed from a bosonic Jordan-Wigner MPO
after converting the fermionic Symmray MPS into the same bosonic JW
representation.

As of 2026-07-03, the direct MPO path is repaired for the tested finite-chain
cases and committed. The fix has two parts:

- The spinful U1U1 FH MPO uses explicit JW endpoint operators:
  `c_i^dag P_i ... c_j` and `P_i c_i ... c_j^dag`, with the overall `-t`
  hopping coefficient.
- `MpsEnergyOptimizer` no longer drops Symmray fermionic dummy-mode phases when
  copying an MPS into bosonic Symmray arrays. For each MPS bond it applies the
  sector phase generated by Symmray's left-to-right fermionic contraction:
  moving the outgoing virtual mode past the local physical leg, flipping the
  contracted mode, and crossing the next tensor's dummy mode when that tensor
  has odd parity.

The old source-term fallback is not used for the direct MPO expectation.

## Empirical Findings

- The mismatch is in the hopping sector, not the onsite interaction. An onsite
  only Hamiltonian matched the term energy, while hopping-only cases showed the
  discrepancy.
- Small tests can pass accidentally. Two-site and low-bond cases did not expose
  the failure reliably; a four-site U1U1 MPS with bond dimension 16 did.
- The failure was not just compression. Both compressed and uncompressed MPO
  probes showed incorrect hopping expectations in high-bond states before the
  MPS bosonization phase was fixed.
- Direct dense comparisons are subtle because Symmray fused indices have a
  charge-ordered dense layout, not necessarily the naive lexicographic basis.
- Naively copying fermionic Symmray blocks into bosonic Symmray arrays loses
  fermionic phases. Calling `phase_sync()` materializes lazy per-block phases,
  but one must also account for contraction phases from virtual-bond
  transposition, contracted-index phase flips, and dummy-mode crossings.
- A simple product of one-site dense creation/annihilation matrices is not
  enough to reproduce all Symmray fermionic two-site contractions. The
  contraction itself carries fermionic swap/Grassmann signs.
- The U1U1 local double-occupancy phase convention matters. Symmray's local
  construction has to be treated as the source of truth; importing ITensor-style
  electron-site matrices without a matching local gauge can flip signs in
  double-occupancy sectors.

## Resolved Mechanism

The core issue was that we were mixing two different fermion encodings:

1. Symmray fermionic tensors implement a local fermionic/Grassmann-like tensor
   algebra with array metadata, phases, labels, and dummy modes.
2. The current MPO construction is a bosonic MPO assembled from dense local
   matrices and parity-string intuition.

That mixture is safe only if the exact bosonization gauge between the Symmray
fermionic tensor basis and the chosen Jordan-Wigner chain basis is applied. The
implemented route is: convert the MPS to a bosonic JW representation with the
derived bond-sector phase, and contract it with a bosonic JW MPO.

The current site-major JW convention for an edge `i < j` is:

- forward hopping: `c_i^dag P_i ... P_{j-1} c_j`
- backward hopping: `P_i c_i ... P_{j-1} c_j^dag`
- coefficient: `-t_sigma`

There is no parity prefix from site 0 and no alternating `(-1)^i` patch. The
left endpoint parity is part of the convention; an earlier intermediate
interpretation that used bare endpoints plus strictly interior parity was not
the final passing implementation.

## External References And Lessons

### TeNPy

TeNPy's Fermi-Hubbard model uses fermionic site objects and inserts
Jordan-Wigner strings through its coupling machinery. Its lesson for us is not
the exact code shape, but the invariant: the string rule is part of the
operator algebra, not a cosmetic sign patch on top of bosonic tensors.

### ITensor

ITensor's Electron site type makes local quantum numbers, onsite operators, and
fermion-string/parity information explicit. This is a useful cross-check for
operator definitions, but its local basis and double-occupancy phase convention
must be reconciled with Symmray before comparing matrices entry by entry.

### MPS-FQE

Sources:

- Repository: <https://github.com/qsimulate/MPS-FQE>
- Paper: <https://arxiv.org/abs/2312.17657>

MPS-FQE is useful as a reference architecture. The paper describes an MPS
extension of Openfermion-FQE for spin-1/2 fermions, using symmetry-adapted MPS,
and the implementation delegates elementary tensor operations to `pyblock3` and
`block2`.

Concrete clues from the code:

- FQE wavefunctions are converted into `pyblock3` sparse tensors with physical
  labels corresponding to empty, alpha, beta, and double occupancy.
- The conversion applies an explicit fermionic sign change between FQE's
  alpha/beta string organization and the MPS occupation ordering.
- MPO construction is delegated to `pyblock3.hamiltonian.Hamiltonian` with
  symbolic creation/destruction operators, rather than manually multiplying
  local dense matrices and hand-inserting every sign.
- Tests compare MPS-FQE MPO expectations directly against FQE exact
  expectations for restricted, diagonal, diagonal-Coulomb, and sparse
  Hamiltonians. This is exactly the style of oracle test we need for Pepsy.
- Time evolution/TD-DMRG can be handed to `block2` after converting both MPS and
  MPO into that backend. That suggests keeping "fermionic algebra correctness"
  in one backend layer, not split between an MPS layer and an ad hoc MPO layer.

MPS-FQE probably does not drop into Pepsy directly: it targets quantum chemistry
Hamiltonians, spatial-orbital spin-adapted sectors, and the `pyblock3`/`block2`
stack. But it helps a lot conceptually: introduce explicit basis/sign
conversion tests and avoid pretending that a local fermionic tensor network is
equivalent to a plain bosonic tensor network plus a guessed parity string.

### Grassmann Tensor Network States

Source:

- Gu, Verstraete, Wen, "Grassmann tensor network states and its renormalization
  for strongly correlated fermionic and bosonic states":
  <https://arxiv.org/abs/1004.2563>

The relevant lesson is that fermionic tensor networks can encode fermion signs
locally using Grassmann variables or an equivalent graded tensor algebra. This
supports the Symmray suspicion: if Symmray is following a local fermionic
tensor approach, then Pepsy should preserve that algebra through MPO
construction and contraction rather than stripping arrays down to bosonic block
data too early.
