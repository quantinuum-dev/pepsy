# Plan: Quimb MPS boundaries for SweepOptimizer

## Status

Implemented:

- `SweepOptimizer(boundary_engine="quimb-mps")`.
- `boundary_engine="auto"` routes Symmray-looking sweep inputs to Quimb MPS and
  keeps dense inputs on Pepsy `BdyMPS`/`CompBdy`.
- Quimb MPS environment storage in `pepsy.optimizers.sweep.environments`.
- Sweep-time scalar normalization/infidelity through Quimb
  `contract_boundary(...)` via Pepsy metric helpers with `method="mps"`.
- Conservative per-slice full-axis environment refreshes.
- `PepsOptimizer(boundary_engine=..., boundary_options=...)` forwards boundary
  policy into sweep cleanup and keeps scalar metric defaults consistent.

Still planned:

- Move more local-objective and trace code out of `sweep.optimizer`.
- Optimize Quimb environment reupdates with narrower ranges once correctness is
  established.
- Add deeper numerical comparisons for dense and Symmray cases.

## Current optimizer layout

The optimizer package now uses subpackages for the state-family optimizers:

```text
pepsy.optimizers.mps.optimizer
pepsy.optimizers.mpo.optimizer
pepsy.optimizers.peps.optimizer
pepsy.optimizers.sweep.optimizer
```

Planned extraction points already exist as modules. The Quimb boundary-provider
work belongs in `pepsy.optimizers.sweep.environments`, with local loss assembly
moving toward `pepsy.optimizers.sweep.local_objective` and trace/progress
helpers moving toward `pepsy.optimizers.sweep.traces`.

## Goal

Add and refine an optional Quimb MPS boundary-environment engine that
`SweepOptimizer` can use for local PEPS slice optimization. The default dense
path should remain the current Pepsy `BdyMPS` plus `CompBdy` engine, while
Symmray-backed PEPS routes to Quimb's MPS environment routines.

The motivation is that `SweepOptimizer` currently stores and updates local
environments only through `BdyMPS.mps_b` and `CompBdy.move_step_bdy(...)`.
That FIT/DMRG path is not a good fit for Symmray. Quimb already exposes
`TensorNetwork2D.contract_boundary(...)` and `compute_*_environments(...)`
for MPS-style boundary contraction, so Pepsy should be able to reuse those
environments in the same local sweep objective.

Quimb reference:
https://quimb.readthedocs.io/en/latest/autoapi/quimb/tensor/tn2d/core/index.html#quimb.tensor.tn2d.core.TensorNetwork2D.contract_boundary

## Current SweepOptimizer flow

1. `SweepOptimizer.__init__` builds `bdy` and `bdy_overlap` with
   `build_bra_ket(...)` and `BdyMPS(...)`, unless both boundary handles are
   supplied.
2. `optimize_axis(...)` normalizes both boundary stores, optionally normalizes
   the state, refreshes the right boundary once, then runs forward/backward
   half-sweeps.
3. Each half-sweep rebuilds the current double layers, creates `CompBdy`
   wrappers, advances one boundary step, and optimizes one row or column.
4. Local losses attach `self.bdy.mps_b[right_key]` and/or
   `self.bdy.mps_b[left_key]` to the local norm network, and similarly attach
   `self.bdy_overlap.mps_b[...]` to the overlap network.

The optimizer therefore assumes the boundary object exposes:

- `mps_b`: key-addressable left/right row/column environments.
- `chi`: current environment bond dimension.
- `expand_bnd(...)`: retune to a larger `chi`.
- `normalize()`: normalize stored boundary tensors before sweeps.
- `norm`: a cheap diagnostic scalar.

## Quimb API facts to preserve

Quimb's 2D boundary API supports:

- `contract_boundary(max_bond=..., cutoff=..., canonize=True, mode="mps",
  layer_tags=..., sequence=..., max_separation=..., final_contract_opts=...,
  progbar=..., inplace=False)`.
- `compute_environments(from_which, xrange=..., yrange=..., max_bond=...,
  cutoff=..., canonize=True, mode="mps", layer_tags=..., dense=False,
  compress_opts=..., envs=..., equalize_norms=...)`.
- `compute_x_environments(...)`, which stores row environments as
  `envs["xmin", i]` and `envs["xmax", i]`.
- `compute_y_environments(...)`, which stores column environments as
  `envs["ymin", j]` and `envs["ymax", j]`.

Important exponent detail: Quimb documents that computed environments only
accumulate exponent generated by the environment contraction. If the source
network already carries a nonzero `tn.exponent`, the caller must include it
when forming local contractions, for example with `select(...,
with_exponent=True)` or equivalent explicit exponent accounting. Pepsy's local
losses already use stripped contractions and manually shift state/target
exponents, so the Quimb path must be tested carefully for double-counting or
missing exponents.

## Implemented design

The first implementation introduces `QuimbMpsBoundaryStore` in
`pepsy.optimizers.sweep.environments`. It exposes the legacy `mps_b`, `chi`,
`expand_bnd(...)`, `normalize()`, and `norm` surface so existing local slice
objective code can attach environments without knowing which engine built
them.

Current providers:

- Pepsy `BdyMPS`/`CompBdy`: still the default dense path.
- `QuimbMpsBoundaryStore`: builds and stores Quimb MPS environments for the
  norm and overlap double layers.

User-facing controls:

- Keep existing `method="dmrg"` defaults for normalization, infidelity, and
  sweep environments on dense inputs.
- Use `boundary_engine={"dmrg", "quimb-mps", "auto"}`.
- In `auto`, choose Quimb MPS when the state or target uses Symmray arrays;
  otherwise keep the existing Pepsy path.
- Forward Quimb controls: `cutoff`, `canonize`, `compress_opts`,
  `equalize_norms`, `layer_tags`, `sequence`, and `mode="mps"`.

## Environment mapping

The provider should let `SweepOptimizer` ask for the environments around
`axis/index` directly. If an adapter exposes the legacy `mps_b` keys, use this
mapping:

- For a column sweep, `axis="y"` and column `j`:
  - left environment: Quimb `envs["ymin", j]`, legacy key `Y{j - 1}_l`
    when `j > 0`.
  - right environment: Quimb `envs["ymax", j]`, legacy key
    `Y{Ly - 2 - j}_r` when `j < Ly - 1`.
- For a row sweep, `axis="x"` and row `i`:
  - lower/left environment: Quimb `envs["xmin", i]`, legacy key
    `X{i - 1}_l` when `i > 0`.
  - upper/right environment: Quimb `envs["xmax", i]`, legacy key
    `X{Lx - 2 - i}_r` when `i < Lx - 1`.

Direct provider methods are preferred over forcing Quimb environments into
`mps_b` names, because Quimb already keys environments by the physical row or
column being optimized.

## Reupdate strategy

Correctness comes first.

Phase 1 recomputes Quimb environments conservatively from the current
double layer whenever a side is advanced. That may be slower than the current
incremental `CompBdy.move_step_bdy(...)`, but it gives a clean regression target
and avoids stale environments after a slice update.

Phase 2 can optimize reupdates using narrower `xrange`/`yrange` calls, shared
`envs` dictionaries, or lower-level `contract_boundary_from_*` routines once
tests prove the key mapping and exponent handling are correct.

During forward sweeps, the environment behind the sweep must include all local
slice updates already accepted. During backward sweeps, the opposite side must
do the same. This mirrors the current `move_step_bdy(...)` behavior and should
be captured in tests with fake environment counters before testing numerics.

## Implementation phases

1. Add provider interfaces and keep the Pepsy provider as a thin wrapper around
   the current code path. Done initially via a Quimb store adapter.
2. Add a Quimb MPS provider that can build full `x` or `y` environment maps
   for a given double layer using `compute_x_environments(...)` and
   `compute_y_environments(...)`. Done.
3. Refactor `SweepOptimizer` local objective construction to request
   environments from the provider rather than directly reading
   `self.bdy.mps_b`.
4. Wire constructor and runtime kwargs so `PepsOptimizer` can route Symmray
   sweep work to Quimb MPS without changing dense-default behavior. Done.
5. Integrate normalization and infidelity defaults so sweep-time
   renormalization does not accidentally fall back to `method="dmrg"` for
   Symmray.
6. Tighten exponent handling with stripped contractions and source-network
   exponents.
7. Add focused tests, then small numerical comparisons.

## Test plan

- Unit tests with fake Quimb-like networks that expose
  `compute_x_environments(...)` and `compute_y_environments(...)`; assert
  options, keys, and refresh timing. Done.
- Unit tests that `SweepOptimizer(..., boundary_engine="dmrg")` keeps the
  current `BdyMPS`/`CompBdy` path.
- Unit tests that `boundary_engine="auto"` selects Quimb MPS for Symmray-like
  data and leaves dense NumPy/Torch/JAX/CuPy defaults unchanged. Partly done
  through `PepsOptimizer` Symmray routing.
- A tiny dense PEPS comparison where Quimb MPS sweep environments and Pepsy
  DMRG/FIT environments produce compatible local losses within loose tolerance.
- Optional Symmray regression tests guarded by `pytest.importorskip("symmray")`.
- Focused commands:
  - `pytest -q -o addopts='' tests/test_optimize_global.py`
  - `pytest -q tests/test_optimize_peps.py`
  - `pytest -q tests/test_prepare_boundary_inputs.py`
  - `pytest -q tests/test_symmetric_tensors.py` when Symmray is available.

## Risks and checks

- Quimb environment exponents can be easy to double count. Test stripped and
  non-stripped paths separately.
- `SweepOptimizer._apply_slice_update(...)` currently calls
  `balance_bonds_()` after local updates. Verify this remains valid for
  Symmray-backed slices, or gate it behind backend support.
- Existing holders `{"bdy": ...}` are part of current API behavior. Preserve
  them for the Pepsy boundary engine.
- Do not add old root-level flat modules while doing this work.
