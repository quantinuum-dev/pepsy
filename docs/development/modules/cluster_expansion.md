# PEPO cluster expansion

`pepsy.operators.cluster` contains two construction layers. The legacy
`ClusterExpansionPlan` is the dense square-lattice implementation of the
connected-cluster PEPO construction. `GraphClusterExpansionPlan` handles an
arbitrary finite `ClusterLattice` with one virtual bond per graph edge and
returns `GraphActivePEPOBlocks`, which materialize as a generic Quimb tensor
network because Quimb's `PEPO` wrapper is square-lattice-only.

`ClusterExpansionPlan` caches lattice directions and cluster-orbit bookkeeping
so different beta values do not rebuild geometry. Both active-block types
store only nonzero virtual-sector blocks; `to_pepo()` is the explicit dense
materialization boundary for square tensors, while graph blocks use
`to_tensor_network()`.

`generate_connected_cluster_shapes()` is the value-independent geometry
inventory for the next implementation stage. It recursively enumerates
translation-canonical connected site sets, records nearest-neighbour and
diagonal bonds, and reports the graph loop number. It keeps rotations
distinct by default, matching the oriented reference inventory, or quotients
them with `quotient_rotations=True` for a C4 planning view. The plan exposes
the same inventory through `connected_cluster_shapes`. The dense builder now
uses the five- through nine-site slices of this inventory for its recursive
generic higher-order path.

The local tensor starts with the one-site exponential in the all-trivial
virtual sector. For order two, the residual of the exact two-site exponential
after subtracting the two one-site factors is decomposed with an operator
Schmidt/SVD factorization. The two endpoint factors occupy one active virtual
direction, while all other virtual directions remain in the trivial sector.

For order three, each unordered pair of lattice directions around a center
site defines a connected three-site path or corner. Its exact cluster
exponential minus the order-two PEPO contraction is projected onto the two
endpoint operator-Schmidt spaces with small pseudoinverses, which is the
factorized equivalent of the dense least-squares solve for the center tensor.
This avoids constructing a large Kronecker design matrix for every cluster.

Order four adds both tree topologies on the square lattice. A T-shaped tree is
solved with a three-active-leg center block. A four-site path is solved by
projecting onto the endpoint channel spaces and factorizing the two-site core
with an internal SVD. The lower-order residual includes disconnected edge
products and adjacent pair-center products already generated by the PEPO.
`max_tree_rank` controls the latter SVD truncation.
This is the dense analogue of the tree-cluster residual solve in the Julia
`ClusterExpansions` reference implementation.

The four-site plaquette is a separate cycle topology. Its residual subtracts
the one-site rail, all four edge channels, all four connected three-site
subtrees, and the two opposite-edge products. It is then written as an exact
tensor ring: each loop bond carries a paired operator-history label, and the
corner tensors enforce the cyclic equality constraints. The dense path uses
matrix units; the fixed Pauli path uses a 16-state pair history, so the
coefficient tensor remains backend-native for autodiff.

For `symmetry="C4"`, the plan uses a symmetric operator-Schmidt gauge and
solves only rotated representatives where the factor map is well-defined.
The remaining active blocks are generated by rotating virtual axes. The
generic P=5/P=6 solver applies the same idea to connected shapes: it maps the
site ordering, parent tree, child ranks, and directions before inserting the
transported factors, and verifies the rotated residual numerically. If a
finite boundary or lower-order gauge prevents that equality, it falls back
to an independent dense factorization. Reversed four-site paths are retained
as separate orientations because reversal also swaps endpoint factors;
treating reversal as a plain axis rotation would be incorrect. This
reduction is restricted to site-symmetric two-site terms; generic anisotropic
models should use `symmetry=None`.

`ClusterExpansionReport` records local residual norms, cluster embedding
counts, retained ranks, and active-versus-dense storage estimates. These are
local diagnostics rather than a global PEPO error bound.

`compose_pepo_layers()` is the Quimb interoperability boundary for multiplying
already-materialized PEPOs. `ClusterExpansionPlan.build_composed()` and
`compose_cluster_expansion_pepo()` use it for the signed Yoshida triple jump
of three order-three layers. The composition is fourth-order in the elementary
step under the order-three/second-order cluster-expansion contract; virtual
bonds grow multiplicatively unless Quimb compression is enabled between
layers. This path deliberately operates on Quimb PEPOs rather than extending
the sparse active-block representation with a second composition algebra.

`ActivePEPOBlocks.compact()` performs orphan removal as a fixed-point pass:
any nonzero block whose active history has no partner on the opposite side of
one of its bonds is discarded, then the surviving integer sectors are
renumbered. This is the sparse equivalent of removing unused history sectors
before native materialization.

`ActivePEPOBlocks.to_symmray_pepo()` maps integer histories to explicit
Symmray virtual charges and packs repeated charges as degeneracy dimensions.
It validates the homogeneous operator charge block by block and uses backend
slice/mask operations for Torch and JAX values. Mixed-charge exponentials are
intentionally rejected at this boundary until their charge components are
split into separate PEPOs.

`PauliPEPOBasis` is the fixed-channel/autodiff path. Its compiled slots are
translation-invariant onsite and positive-edge Pauli terms. Evaluation builds
local cluster exponentials with backend-native matrix exponentials, expands
the connected residuals in the physical Pauli basis, and inserts those
coefficients into predeclared active sectors. The coefficient-to-Pauli slot
assembly is fused, and value-independent physical embedding maps are cached
by `compile_exp()`. The fixed channels are larger than the SVD reference but
do not change rank when coefficients change, which is the key invariant for
repeated Torch/JAX evaluations. It intentionally returns
`ActivePEPOBlocks` by default; dense materialization is an explicit
small-system boundary. Use `basis.exp(step, ...)` for one-off calls or
`basis.compile_exp().exp(step, ...)` for repeated calls. `evaluate` and
`time_evolution` remain compatibility aliases. It covers tree and
plaquette-loop orders 1–4; PEPO–PEPS contractions remain outside this
operator-construction API.

`PEPOClusterProductExpansion` is the joint ordered-residual path. It retains
the supplied `A`, `B`, `C`, ... objects as local Hamiltonian sources, and for
each connected spatial cluster `S` forms
`W_S = exp(A_S) @ exp(B_S) @ exp(C_S) @ ...` before subtracting products of
lower connected residuals. The resulting channels are assembled once into one
PEPO. It never constructs an independent full-lattice PEPO for each factor.
This is the same local-residual definition used by the MPO cluster engine;
only the final tensor topology differs. All factors must share the lattice,
symmetry policy, and cluster order.

### Cluster order and dimension accounting

The cluster order `p` is a joint spatial cutoff, not a factor index. For
local physical dimension `d`, a `p`-site dense cluster target has matrix shape
`(d**p, d**p)` and `d**(2*p)` operator coefficients. Thus the local work is
exponential in `p`, while for fixed `p` the number of cluster embeddings grows
with the lattice size rather than with the full Hilbert-space dimension
`d**N`. The PEPO bond dimension is the accumulated rank of the connected
residual channels and their graph-history sectors; it does not multiply three
full factor-PEPO bond dimensions. Use the smallest `p` that resolves the
desired spatial correlations, and use optional compression only as a further
bond-rank approximation.

The dense path supports orders five through nine through a separate recursive
generic stage. For each level it contracts the already-built lower-order
active PEPO on each candidate support with zero boundary sectors, subtracts
that lower operator from the exact local exponential, and factorizes the
residual over a spanning tree. Thus P=6 subtracts the P=5 correction, and
P=7–9 continue the same recurrence rather than jumping directly from P=4.
This keeps the residual definition aligned with the actual Quimb PEPO rather
than an idealized inclusion-exclusion formula. `ClusterModelAdapter` and
`build_model_cluster_expansion_pepo` provide finite dense Ising, Heisenberg,
XXZ, and custom local-term entry points. The fixed-channel Pauli path still
covers tree and plaquette-loop orders 1–4; native Symmray solving and graded
fermionic MPO histories remain separate future subsystems.

`build_real_time_cluster_expansion_pepo()` is the coefficient-dependent dense
entry point. It assembles weighted local terms before forming the complex
cluster exponential, then optionally hands generic residuals to Quimb's tree
and ALS fitters. The fit target and factorization truncation are reported
separately; the latter is a numerical optimization and is not part of the
autodiff fixed-channel contract.

Generic cyclic residuals can opt into adaptive ALS ranks. The solver tries a
rank schedule from `loop_rank_start` through `max_loop_rank`, always including
the configured cap, and uses the previous fit as the initial tensor data when
`fit_warm_start=True`. This is intentionally a local residual improvement:
it does not choose projectors from the environment of the full PEPO. The
report separates these attempts as `generic_loop_solved` and
`generic_loop_rank`; `loop_rank` remains the overall report, including the
explicit four-site plaquette history rank.

`ClusterInternalSymmetry` is an explicit validation/metadata boundary for
neutral `U1`, `Z2`, `U1U1`, and `Z2Z2` terms. It is intentionally separate from
geometric C4 orbit reduction. Dense SVDs are not treated as native graded
factorizations; explicit virtual charges are still required for Symmray
conversion, and fermionic graded solving remains in the native fermion
subsystem.

The BP loop-cluster API is intentionally not part of this operator builder.
`pepsy.bp.loop_cluster_expand()` expands a tensor-network contraction around
BP messages, while the connected-cluster PEPO expansion subtracts lower-order
operator contributions from local exponentials. BP can later provide
environment-aware PEPO/PEPS contraction diagnostics or truncation objectives,
but it cannot replace the local residual solver needed for orders five and
above.
