# 2026-09-25 — Lightweight routine CI

- Scope: reduce CI cost as requested, retaining a full scheduled/manual check.
- Branch / baseline: `develop` / `99836fb`.
- Commit status: prepared for the authorized commit and push to `develop`.

## Changes

- Routine CI has three jobs instead of eight: core checks, package, and docs.
  Core combines minimum-dependency tests, Ruff, focused mypy, and the skill
  catalog. Removed duplicate syntax/lint work and unnecessary tool installs.
- Full optional-backend tests, including VMC/NetKet, now run only in the
  nightly/manual workflow, retaining the 60% whole-package coverage gate.
- MPI moved to that workflow. Unit tests run once; two- and three-rank
  integration and benchmark checks share one runtime/dependency installation.
- Both workflows cache pip downloads from the package metadata and cancel
  superseded runs on the same ref. Fast jobs have ten-minute timeouts; the
  full suite retains its 90-minute bound.
- Updated [Contributing](../CONTRIBUTING.md#what-ci-checks) with schedules,
  manual branch selection, and the distinction between routine and full CI.

## Boundaries

The prior extended job took about 31 minutes; removing it from routine
pushes is the main saving. New timings must be measured after hosting.
Optional/slow regressions can wait until the next full run. Caching reduces
repeat downloads, not numerical test time.

GitHub schedules use the default branch. Until these changes reach `main`,
its existing scheduled workflow remains active; the updated full workflow
can be run manually on `develop`. This change does not merge branches or
alter release publication. Releases remain GitHub artifacts only.
